# EduAI Audit: запуск и работа

Приложение проверяет готовые вероятности по уже известным исходам. Оно показывает,
кого выбрали для проверки, сколько положительных случаев нашли или пропустили,
сколько возникло ложных тревог и как результаты различаются между группами.

## Запуск на Windows

Нужен Python 3.11 или новее. В терминале PyCharm из корня репозитория выполните:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

После первой установки запускайте `start_app.bat` двойным щелчком. Он включает
сервер в фоне, ждёт его готовности и открывает приложение в браузере. Повторный
запуск открывает уже работающее приложение. Держать терминал открытым не нужно.
Журнал запуска находится в `.venv/eduai-app.log`.

Ярлык на рабочем столе **EduAI Audit** запускает ту же установленную копию.
Он связан с текущей папкой проекта и её средой Python. Для ручного создания
ярлыка укажите `.venv\Scripts\pythonw.exe`, полный путь к `launch_app.py` в кавычках
как аргумент и папку проекта как рабочую папку.

После закрытия вкладки сервер продолжает работать до завершения Windows. Адрес
[127.0.0.1:8501](http://127.0.0.1:8501) доступен только на этом компьютере;
телеметрия Streamlit отключена.

## Первый аудит

Для запуска без установленного Python предусмотрен установщик Windows:
`EduAI-Audit-Setup-0.1.0.exe`. Он устанавливает приложение для текущего пользователя
и создаёт ярлык. Интерфейс установленной версии открывается в браузере на порту
8502; версия из исходного проекта продолжает работать на 8501.
Команда **Stop EduAI Audit** в меню «Пуск» останавливает приложение. Закрытие
вкладки браузера оставляет локальный сервер работающим. Удаление приложения
доступно через настройки Windows; журналы запуска находятся в
`%LOCALAPPDATA%\EduAI-Audit`. Инструкция по сборке — в `packaging/README.md`.

1. Откройте приложение и выберите **Русский** в поле **Language / Язык**.
2. Нажмите **Попробовать пример**. Данные и настройки загрузятся автоматически.
   Это вымышленные данные для знакомства с интерфейсом.
3. Проверьте заполненные поля. Для двух прогнозов можно вместо этого нажать
   **Попробовать сравнение** — обе колонки будут выбраны автоматически.
4. Оставьте доли `15, 20, 30` и долю подробного отчёта `20%`.
5. Нажмите **Запустить аудит**. Просмотрите результаты, графики и таблицы.
6. Скачайте HTML-отчёт: он открывается без интернета и включает таблицы и графики.

Чтобы вернуться к своему файлу, нажмите **Перейти к своему CSV** или загрузите
новый CSV. Результаты примера будут убраны. Настройки примера отделены от настроек
загружаемых файлов. Пример можно также скачать и настроить вручную через пресет
**Синтетический пример**.

Переключать язык можно до или после расчёта: настройки и результаты сохраняются.
Имена столбцов и коды групп остаются как в источнике. Настройки выбираются из
списков без ввода текста. Можно выбрать доли отбора от 1% до 100% с шагом 1%.
Название выборки выбирается из имени файла и названия пресета; момент прогноза
и период исходов — из готовых вариантов. Если подходящего варианта нет,
оставьте «Не указано».

## Какие данные нужны

Одна строка CSV должна описывать одну единицу аудита. Нужны известный исход,
готовая вероятность положительного исхода от 0 до 1 и уникальный ключ решения.
Обучение модели и подготовка прогнозов выполняются отдельно. Инструкции по
выгрузке из тетрадки — в [EXPORT_PREDICTIONS.md](EXPORT_PREDICTIONS.md).

| Пресет | Единица аудита | Исходы | Ключ решения |
| --- | --- | --- | --- |
| UPV 2022 | Студент после подготовки исходных строк по курсам | `A` — положительный, `B` — отрицательный | `dni_hash` |
| OULAD | Запись студента на курс за учебный период | `Withdrawn` — положительный; `Pass`, `Fail`, `Distinction` — отрицательные | `id_student`, `code_module`, `code_presentation` |
| UCI | Студент при предположении «одна строка — один студент» | `Dropout` — положительный; `Graduate` — отрицательный; `Enrolled` исключается | `Source Row ID` — технический ключ |

**Ключ решения** отличает одну проверяемую запись от другой. Для UPV достаточно
ID студента; в OULAD нужны студент, курс и учебный период. Приложение отклоняет
повторы ключей и не объединяет строки автоматически.

**ID студента** связывает несколько записей одного человека для расчёта
неопределённости. В UCI реального ID нет: технический номер строки не доказывает
отсутствие повторяющихся студентов. Если ID решения вообще отсутствует, номер
строки можно включить явно; отчёт укажет это ограничение.

**Базовая группа** задаёт точку отсчёта: другая группа минус базовая. Например,
Recall TP 40% минус Recall TC 50% даёт −10 процентных пунктов. В пресете UPV
базой для `dedicacion` является TC, как в PROTOTYPE. Для остальных столбцов база
не выбрана. Изменение базы не меняет отбор и показатели самих групп.

## Как читать результаты

- Названия метрик остаются английскими: Recall, Precision, False-Positive Rate
  (FPR), Marginal Precision. Пояснения по-русски появляются при наведении на
  значок справки; в скачанном HTML-отчёте наведите на «?» рядом с метрикой.
- Доли отбора применяются после исключения исходов; число выбранных строк
  округляется вверх. При равных вероятностях используется исходный порядок строк.
- Подробные результаты по группам относятся к выбранной доле отчёта. На графиках
  представлены все рассчитанные доли.

### Сводка перед запуском

После заполнения настроек приложение проверяет данные теми же правилами, что
и тетрадка. Сводка показывает строки на входе, исключённые и проверяемые строки,
положительные и отрицательные исходы, число различных указанных ID студентов
и пропуски в группах после исключений. Ранжирование и интервалы на этом этапе
не рассчитываются. Повторы ключей и неверные вероятности видны до запуска.

### Графики групп

В разделе «Показатели групп при выбранной доле» выберите столбец группы.
Точки показывают Recall и FPR, отрезки — доступные доверительные интервалы.
Подсказки содержат статус интервала, знаменатель и замечания о числе наблюдений.
Недоступный интервал не заменяется нулём; неопределённая метрика подписана.
В HTML-отчёт входят графики всех выбранных столбцов групп при фокусной доле.

### Повторное использование настроек

Кнопка «Сохранить настройки JSON» сохраняет выбор столбцов и исходов, группы,
базы, доли, контекст, разделитель и кодировку CSV. В следующий раз загрузите
CSV и JSON в разделе «Загрузить сохранённые настройки», затем нажмите
«Применить настройки». Приложение сначала проверит их на текущем CSV.
Если настройки несовместимы с данными, текущий выбор останется прежним.
JSON не содержит записей студентов, прогнозов или результатов аудита.

### Скачивание таблиц

После аудита выберите таблицу и нажмите «Скачать выбранную таблицу CSV» или
скачайте все шесть таблиц одним ZIP-архивом. Экспорт содержит все рассчитанные
доли отбора, числовые значения без округления для экрана и исходные коды.
Кодировка — UTF-8 с BOM, разделитель — запятая. Пустая числовая ячейка означает
недоступное значение. Файл manifest.json в архиве описывает состав выгрузки;
предположения и ограничения расчётов приведены в HTML-отчёте.

Интервалы относятся к фиксированным прогнозам и отбору. Они не учитывают новое
обучение модели и изменения будущих наборов студентов. Для малых или разреженных
групп показаны замечания; некоторые интервалы недоступны. Разница между группами
не является автоматическим выводом о дискриминации или причинности. Приложение
не выбирает оптимальную долю отбора.

Режим без известных исходов и AI-объяснения запланированы отдельно.

## Сравнение двух прогнозов

В одном CSV должны быть известные исходы, ключи решений и две колонки готовых
вероятностей. Обе колонки относятся к одному положительному исходу, моменту
прогноза и периоду наблюдения исходов. Обучение моделей выполняется отдельно.

1. Загрузите CSV и выберите пресет или настройте столбцы.
2. Включите «Сравнить две колонки прогнозов».
3. Выберите колонки вероятностей моделей A и B, общие исходы, группы и доли.
4. Запустите аудит. Результаты моделей и разницы B минус A появятся рядом.

Приложение покажет Recall, Precision, FPR и числа найденных и пропущенных
случаев и ложных тревог. Пересечение отбора разделено на записи, выбранные
обеими моделями, только A, только B и ни одной. В раскрываемом списке записей
можно посмотреть ключи, исходы и обе вероятности и скачать выбранные записи CSV.
Номер исходной записи считается по строкам данных до исключений.

Для записей на курс пересечение относится к решениям, а не различным студентам:
один человек может встречаться несколько раз. Отбор общий для всей выборки,
а показатели групп описывают этот отбор. Равные вероятности разрешаются по
исходному порядку CSV. Неверные вероятности отклоняются даже в исключаемых строках.

Интервалы рассчитаны отдельно для каждой модели по проверенным функциям тетрадки.
Разница B минус A — наблюдаемый результат; парные интервалы и проверка значимости
разницы не рассчитываются. Приложение не выбирает лучшую модель автоматически.

Можно скачать общий HTML-отчёт и ZIP с общими таблицами и таблицами каждого
отдельного аудита. ZIP не содержит таблицу индивидуальных записей: она скачивается
отдельной кнопкой. JSON версии 2 сохраняет выбор обеих колонок; старые настройки
версии 1 продолжают работать в режиме одного прогноза.

Для знакомства нажмите **Попробовать сравнение**, затем **Запустить аудит**.
При доле 20% каждая модель выберет 4 из 16 проверяемых записей: A найдёт 2 случая
с 2 ложными тревогами, B — 4 случая без ложных тревог. Две записи выберут обе
модели, ещё по две — только A и только B. Все данные и вероятности вымышленные.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -v
```

Проверки охватывают входные данные, расчёты и интервалы, соответствие отчёта
расчётам, пресеты, перевод, графики и переключение языка без повторного аудита.
